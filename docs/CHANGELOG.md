# Changelog — правило для команды

Любое **техническое изменение** сайта Hello I Am Studio (логика, API, интерфейс, роутинг, деплой) **обязательно** попадает в changelog — как контроль версий в GitHub Releases.

## Что логируем

| Логируем | Не логируем |
|----------|-------------|
| Новые рубрики, шаги пайплайна, кнопки | Контент постов (тексты, картинки) |
| Фиксы превью / экспорта / генерации | Одноразовые правки copy в постах |
| Новые API-эндпоинты | Локальные эксперименты без мержа |
| Изменения навигации и экранов | Генерация эмодзи/картинок как контент |
| Инфра (Docker, Traefik, env) | |

## Куда писать

**Источник правды:** [`data/changelog.json`](../data/changelog.json)

UI: **Systems → Changelog** (`#/systems/changelog`).

## Как добавить запись

1. Открой `data/changelog.json`.
2. Найди блок с текущей версией (`productVersion` в корне) или создай новый объект в `entries[]` (сверху — новее).
3. Добавь объект в `changes[]`:

```json
{
  "type": "feature",
  "area": "content",
  "summary": "Краткий заголовок одной строкой",
  "details": "Что изменилось и зачем. Достаточно 1–2 предложений."
}
```

### Поля

| Поле | Значения |
|------|----------|
| `type` | `feature` · `fix` · `ui` · `api` · `infra` · `docs` |
| `area` | `systems` · `content` · `brand` · `site` · `export` · `generation` · `settings` · `routing` · `assets` · `deploy` |
| `summary` | Заголовок (как commit subject) |
| `details` | Пояснение (как PR description) |

### Новая версия

При заметном релизе добавь **новый** элемент в `entries[]`:

```json
{
  "version": "0.2.1-alpha",
  "date": "2026-06-20",
  "title": "Короткое название релиза",
  "changes": []
}
```

Обнови `productVersion` в корне файла.

## Чеклист перед деплоем

- [ ] Есть запись в `data/changelog.json` для каждой техфичи в этом деплое
- [ ] `summary` понятен без контекста чата
- [ ] При смене версии обновлён `productVersion`

## Связь с git

Changelog **дополняет** git, не заменяет: в git — diff, в changelog — смысл для продукта и команды.
